    Private JS/WASM package preparation¶

    The canonical package.json defines the independent opentlv-js version. The first standalone release is 0.1.0 (#32), prepared against Core v0.8.0. The earlier 0.1.0-dev.0 was an unreleased development identity, not a previous JS release; there were no JS repository tags or GitHub releases when checked on 2026-10-28. The JS version is not the pinned Core version: change it explicitly when advancing the binding; a Core pin change never changes it automatically. Record binding changes under Unreleased in CHANGELOG.md.

    Release tags are vMAJOR.MINOR.PATCH and must equal v plus the package.json version, the component_version in docs-examples.json and the heading of ci/release-notes.md. Prerelease tags and npm dist-tags are not used.

    The name opentlv-js identifies this repository and its package archive. No npm registry name or scope is selected or reserved. private: true makes npm refuse publication, as described in the npm package metadata contract. No npm publish command, registry credential or lifecycle hook is added. The GitHub release workflow attaches the tested archive to a GitHub release only.

    Build and check¶

    Activate Emscripten 4.0.10, Node 22 (including npm) and TypeScript 5.9.3 (tsc on PATH), then run:

    emcmake cmake -S . -B build-wasm -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build-wasm --target opentlv-wasm --parallel
ctest --test-dir build-wasm --output-on-failure --no-tests=error
python -B scripts/package.py --build build-wasm --output build/package-check

    Use the default pinned Core build. The command verifies its live source receipt and rejects sibling development overrides. It checks all four nonempty outputs in <build>/dist/, the WASM header and wrapper equality with src/*.mjs. It runs the smoke, Format/field and Reader/Writer streaming suites and their parse, fields and streaming examples against the installed package. It also runs the Document/Schema suite and example, and compiles the installed TypeScript consumer with strict NodeNext and Bundler resolution. These checks establish local package consistency, not attestation of arbitrary prebuilt binaries. CI builds the inputs afresh before packaging.

    The output directory must be new. The script stages an exact file allowlist, generates version.mjs from package.json, and runs npm pack first with --dry-run, then as a local archive. Both calls use --offline --ignore-scripts. The actual archive must contain exactly the expected regular files, with the expected SHA-256 bytes; missing, extra, duplicate and symlink entries fail.

    It then installs the archive into an isolated consumer using offline npm with scripts, audit and funding requests disabled. The consumer checks every public export, the independent version, the preserved Core version, WASM asset lookup, default/explicit loader locations and parsing. The original smoke/parse checks and the generic field/streaming suites and examples run against the installed archive. CI also runs the Core-owned Query fixtures through the installed package's original facade runner.

    The source checkout is a metadata/build source, not an installable package: generated index.mjs, version.mjs and dist/ live only in the staging area. Do not pack or install the source root directly. For local experimentation, install the checked build/package-check/opentlv-js-<version>.tgz archive. The exact archive name, hashes and commands are in build/package-check/result.json.

    API and evidence¶

    The package README describes each export and asset location. The four original runtime filenames remain unchanged; API additions are tracked separately from the immutable migration baseline. packaging/index.mjs re-exports the existing facade and adds packageVersion. The opentlv-js/version subpath exposes that value without loading the facade. Existing (await loadOpenTLV()).version and the C bridge version entry point continue to identify Core, preserving their migration contract.

    package-info.json includes binding identity and separate immutable Core source identity/output hashes. It excludes machine-specific build paths so identical builds can produce identical packages. Node 22 is the validated runtime; ESM is the only package module interface. The exact 21-file archive includes four .d.mts declarations, with types exports for the root, facade, Query and version entry points. TypeScript 5.9.3 checks both NodeNext and Bundler resolution; this does not establish browser/worker or bundler runtime compatibility. CommonJS and CDN support are not claimed.

    The package keeps license: "MIT" for original binding code and includes the root LICENSE, LICENSES/MIT.txt, THIRD_PARTY.md and four upstream notices/ files for Core, Emscripten, musl and compiler-rt. The generated version.mjs has the binding's SPDX/author header. Runtime JS/WASM retains its upstream ownership; the package MIT field does not replace those terms. Missing, empty or symlinked notices fail staging, and archive/installed-consumer checks verify their exact bytes. Keep notices with copied runtime assets. See dependency attribution before changing Core or toolchains.

    All CI tiers run package checks. The double-build tier in Full CI also compares the complete private archive hash, metadata and file hashes across two independent builds and uploads the first build's archive as js-package-<attempt>. Package reports keep published and release_verified false: they are build results. A passing local run does not establish hosted CI or a verified release.

    GitHub release¶

    The manual JS Release workflow (js-release.yml) accepts an unused tag matching the versions above. Changes stay under Unreleased during development; close the changelog under the matching version without the tag's v prefix and the release date before dispatching the release (for example, ## [0.1.0] - 2026-10-28). The release rejects a changelog without that section. The versioned release notes are the publication text.

    1. Review and merge the release preparation. Wait for successful JS Main CI on that exact commit. Dispatch JS Release on main with tag: v0.1.0.
    2. scripts/release.py prepare rejects a missing, unprefixed or otherwise malformed tag, a foreign, dirty or non-main checkout, a dispatch from another workflow revision, a changed main tip, an existing tag or release, differing versions, notes or changelog, a Core lock that is not an exact v release tag commit (currently Core v0.8.0), and missing or failed Main CI, including its JS quality gate (#34).
    3. The workflow then runs Full CI in the same attempt: Release and Debug, the double-build reproducibility tier, migration compatibility, package checks and both quality gates.
    4. Assembly revalidates the request and every Full record against the commit, run, attempt and Core lock. It copies the exact opentlv-js-<version>.tgz whose SHA-256 and file hashes the reproduced builds recorded; it does not rebuild it. The workflow attests all four assets: the archive, release-manifest.json, release-notes.md and SHA256SUMS.
    5. Publication rechecks evidence, checksums, attestations and unused tag status, then creates the tag and a draft release. Only after the uploaded asset names, sizes, SHA-256 digests, notes and tag commit match does it publish the draft and verify the public result. It emits js-published-<attempt> with the URL, source and asset identities.
    6. Record the published URL, exact commit, Main and release run links in issue #32 and Core epic #718. Close the tracking only after publication and asset verification.

    If a failure occurs after creating a tag or draft, inspect that state before retrying; the workflow refuses to overwrite either. Earlier attempts' artifacts cannot satisfy a new attempt. A new main commit or Main run requires a new release attempt. No workflow has a tag-push trigger, so creating or pushing a tag cannot run checks or publish outside this gated workflow; a regression test enforces this for every workflow.

    Install a downloaded release archive after checking it against SHA256SUMS and its attestation:

    gh attestation verify opentlv-js-0.1.0.tgz --repo OpenTLV/opentlv-js
npm install ./opentlv-js-0.1.0.tgz

    The archive contains the four runtime files, so consumers do not need Emscripten or Core. packageVersion reports 0.1.0; the existing (await loadOpenTLV()).version reports the embedded Core 0.8.0.

    Local preparation evidence (2026-10-28)¶

    WSL Ubuntu with Emscripten 4.0.10, Node 22.16.0 and TypeScript 5.9.3 passed the PR and Main tiers of scripts/ci.py against the fetched Core v0.8.0 pin: all CTest suites, the Core-owned Query fixtures through the source and installed facades, the wasm32 Query ABI check and the installed 21-file archive with its runtime, example and TypeScript checks. Both tiers produced the same archive SHA-256. The changed migration gate was run on its own against the PR build: the reconstructed migration sources rebuilt from ci/migration-core-source.json matched all four historical Core outputs. The Python infrastructure suite passed on Linux and Windows. The Core API report lists 197/197 generic symbols referenced with 100 exclusions, and the Core pin diff adds or removes no public symbols.

    Full CI (Debug, double build), attestations and publication were not run locally; they require the hosted release run on the merged commit. Local logs are under build/issue32-validation/; they are not committed release evidence.
