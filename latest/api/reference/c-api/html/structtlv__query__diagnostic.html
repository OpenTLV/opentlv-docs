Detailed Description

Fixed-layout compiler/execution failure, initialized by diagnostic entry points.

Note
Every field has one meaning. Result, severity, primary location, path and expected text live only in diagnostic; lower-layer evidence lives only in the detail.causes frames. Direct Reader failures retain detail.reader; conversion callback violations are Query-owned and preserve the raw reported result.
After initialization, every non-TLV_OK return has a kind other than TLV_QUERY_ERROR_NONE. TLV_ERR_INVALID_STATE has kind TLV_QUERY_ERROR_STATE. Invalid arguments and configuration (TLV_ERR_NULL_ARG, TLV_ERR_INVALID_ARG) have kind TLV_QUERY_ERROR_ARGUMENT unless a Reader, conversion or Tag adapter result is preserved. Reader failures and TLV_NEED_MORE_DATA retain the returned code in diagnostic.code and set cause to TLV_QUERY_CAUSE_READER. Success need not clear old detail.
Pre-initialization overlap, reentrancy and failed-execution guards leave this output untouched. Compiler prepare/commit/load preflight argument, extent and alignment checks can also reject before initialization.
A valid bind, feed or finish call on an already failed execution returns INVALID_STATE without writing this object, preserving the original failure when it is reused. Inspect exec_info.invalid and reset before continuing.
This value type is not extensible; changing its layout requires an ABI change.
