    Build only the components you need¶

    OpenTLV builds only the components you ask for. This guide gives ready-made CMake recipes for the common selections. For the principle and the option reference, see include only what you need and build configuration.

    Core, IO, Document, Generator, Query, Schema and Codec are independent C libraries. Core owns Definition, Format and Field Encoding, Element and Layout, byte utilities and generic diagnostics. IO owns Reader, Writer, traversal and serialization and depends publicly on Core. Document owns mutable trees and depends publicly on Core and IO. Generator owns deterministic wire generation, with public Core and private IO dependencies. IO does not build or link Generator.

    C and C++ use the same targets¶

    project(editor LANGUAGES CXX)
find_package(OpenTLV REQUIRED CONFIG COMPONENTS Document QueryDocument DocumentCodec)
target_link_libraries(editor PRIVATE OpenTLV::Document OpenTLV::QueryDocument OpenTLV::DocumentCodec)

    OPENTLV_BUILD_CXX controls C++ tests, examples, benchmarks and property tools. It does not control module availability or installed headers. A project(app LANGUAGES C) consumer can link the same targets without enabling a C++ compiler. Functional targets publish the required include paths and compile features. Use OpenTLV::IOCodec with opentlv/codec/writer.hpp for typed Writer overloads. No extra include directories or separate C++ target are needed.

    Core, IO and Document¶

    Select functionality by linking the target you use:

    find_package(OpenTLV REQUIRED CONFIG COMPONENTS Core IO)
target_link_libraries(my_parser PRIVATE OpenTLV::IO)
# For generic primitives without Reader/Writer:
target_link_libraries(my_format_tool PRIVATE OpenTLV::Core)

    The same targets are available through add_subdirectory() and FetchContent. A Core-only package consumer can request just COMPONENTS Core; no IO or C++ library is loaded. All extracted modules support static and shared builds, selected by OPENTLV_BUILD_SHARED_LIBS. A library-only build does not require a C++ compiler, including when C++ headers are installed.

    Build only the required target from a checkout:

    cmake -S . -B build/modules -DOPENTLV_BUILD_TESTS=OFF -DOPENTLV_BUILD_EXAMPLES=OFF
cmake --build build/modules --target opentlv_core
# Builds Core and IO, without the remaining library implementations:
cmake --build build/modules --target opentlv_io
# Builds Document and its Core/IO dependencies only:
cmake --build build/modules --target opentlv_document
# Builds Generator and its Core/IO dependencies only:
cmake --build build/modules --target opentlv_generator

    OPENTLV_READER, OPENTLV_WRITER, OPENTLV_DOCUMENT, OPENTLV_QUERY, OPENTLV_SCHEMA and OPENTLV_CODEC are no longer CMake options. Supplying any of them is an error; remove them from presets and existing caches (or use a fresh build directory). IO always includes both APIs. The corresponding preprocessor macros, tlv_config_*() availability mirrors and tlv/config.h have been removed. Query features remain in opentlv/query/features.h.

    The optional OpenTLV::tlv interface aggregates Core, IO, Document, Generator, Query, Codec, Schema and their extracted integrations transitively. Direct library consumers must link the dependencies too (static link order: opentlv_schema_query_document, opentlv_schema_query, opentlv_schema_number, opentlv_codec_structure, opentlv_query_document, opentlv_query_codec, opentlv_query, opentlv_document, opentlv_generator, opentlv_codec, opentlv_schema, opentlv_io, opentlv_core). Shared deployments must distribute all linked libraries. Rebuild consumers after the split; the old single-library binary distribution is not preserved.

    OpenTLV::tlv is an INTERFACE target: it produces no archive or DLL. The separate tlv++ target and tlv++ package component are removed; link the functional target in either language.

    Public Reader/Writer headers and function signatures remain at their existing paths. tlv_copy_element() now belongs to opentlv/io/writer/copy.h; Core opentlv/core/copy.h contains raw byte/value copies only. opentlv/tlv.h includes both. New public utility headers are opentlv/core/utf8.h, opentlv/core/callback.h and opentlv/core/diagnostic/cause.h. Module exports use OPENTLV_CORE_API, OPENTLV_IO_API, OPENTLV_DOCUMENT_API and OPENTLV_GENERATOR_API; CMake propagates the matching static-build definitions automatically.

    Independent Document¶

    find_package(OpenTLV REQUIRED CONFIG COMPONENTS Document)
target_link_libraries(my_editor PRIVATE OpenTLV::Document)

    This loads only Document, IO and Core. Include opentlv/document/document.h for ownership, topology, mutation, parsing and serialization. Document requires no Query, Schema, Codec, Generator or builtin implementation; supply a Format.

    Include opentlv/query/document.h explicitly for Document Query operations previously declared by opentlv/document/document.h. The aggregate opentlv/tlv.h still includes both. Link OpenTLV::QueryDocument for these operations; linking Document alone does not provide Query symbols. Include opentlv/document/document.hpp and link OpenTLV::Document for the header-only C++ facade. Query methods retain their names but their definitions come from opentlv/query/document.hpp and OpenTLV::QueryDocument. Typed node decode() and get() definitions come from opentlv/document/codec.hpp and OpenTLV::DocumentCodec. opentlv/query/diff.hpp belongs to QueryDocument because its selection and failure contract uses Query. The umbrella opentlv/tlv.hpp includes all integrations for existing full-API source usage.

    opentlv/document/integration.h defines the public integration boundary: effective options and allocator access, live-node ownership checks, callback activity and nested callback lifetime guards. Integrations use existing node traversal, identity, retirement epoch, revision and mutation APIs. Guarded fallible edits fail with INVALID_STATE; erasure and destruction are deferred until the outermost guard exits. No Document private header is needed by Query.

    Independent Codec¶

    find_package(OpenTLV REQUIRED CONFIG COMPONENTS Codec)
target_link_libraries(my_values PRIVATE OpenTLV::Codec)

    This loads only Codec and Core. A target-only source build with cmake --build build/modules --target opentlv_codec compiles no Reader, Schema, Query, Document, Generator or builtin implementation. All generic numeric, digit, text, IPv4 and byte conversions, callbacks and measurement remain available. Public headers retain their opentlv/codec/ paths and use OPENTLV_CODEC_API.

    Link OpenTLV::QueryCodec and include opentlv/query/adapters.h for generic Query conversion providers. This integration depends explicitly on Core, IO, Query and Codec. Neither base module links the integration.

    opentlv/codec/structure.h belongs to the Codec-owned codec-structure integration, which composes Codec, Schema and IO. Link OpenTLV::CodecStructure; the aggregate continues to provide structured validation and conversion without changing wire behavior. No base Codec dependency points back to Schema or the aggregate.

    Codec diagnostics now store a leaf codec detail and a separate causes chain. Use the producer's tlv_reader_detail_copy() or tlv_schema_detail_copy() on a cause frame instead of codec.cause and codec.detail. Common locations, paths, expected/actual text and conversion operation, raw result, reason, representation and callback violation are preserved. tlv_codec_diagnostic_export() prepends the Codec frame while preserving delegated frames and bounded omission counts; tlv_codec_detail_import() copies only the outer Codec leaf. Legacy cause enum names remain available for the approved baseline mapping. Rebuild binary consumers. C++ codec_failure::causes() exposes the retained chain.

    Include opentlv/codec/writer.hpp for typed writer_base::write() overloads. opentlv/codec/typed.hpp no longer includes Writer. The aggregate opentlv/tlv.hpp includes both. Common C++ error support no longer includes Schema headers.

    Independent Schema¶

    find_package(OpenTLV REQUIRED CONFIG COMPONENTS Schema)
target_link_libraries(my_validator PRIVATE OpenTLV::Schema)

    Only Schema, IO and Core are loaded. A source build with cmake --build build/modules --target opentlv_schema compiles no Codec, Query, Document, Generator or builtin implementation. Length constraints, structural rules, occurrence/order checks, preparation and diagnostic reports remain available. Supply a Format; builtin Formats are optional consumers of the generic contract.

    Select integrations explicitly:

    Target Header Behavior
    OpenTLV::SchemaNumber opentlv/schema/number.h Schema-backed numeric conversion and length diagnostic composition
    OpenTLV::SchemaQuery opentlv/schema/query.h Contextual assertions over buffers
    OpenTLV::SchemaQueryDocument opentlv/schema/query_document.h Contextual assertions over Document, including D plans
    OpenTLV::CodecStructure opentlv/codec/structure.h Object conversion with structural validation

    Base modules do not depend on these integrations. Rules retain their order, context selection and execution semantics; assertion failures retain the rule index, name, tag, path and available source location. Query execution failures keep their original cause and result. The aggregate includes all integrations.

    tlv_schema_diagnostic_t keeps Schema findings in detail.schema. For TLV_SCHEMA_CAUSE_READER or TLV_SCHEMA_CAUSE_CODEC, inspect detail.causes using the producer's tlv_reader_detail_copy() or tlv_codec_detail_copy(). Direct detail.reader and detail.codec members are removed. Diagnostic copies retain their external borrows; codes, classifications and evidence are unchanged. The cause discriminator keeps its existing numeric vocabulary for compatibility.

    C++ Schema validation, reports and preparation return schema_failure, declared in opentlv/schema/error.hpp. It retains schema_kind(), definition() and definition_kind(), exposes the complete diagnostic with native(), and provides failure() / to_error() for common status, location and path. Those Schema-specific accessors no longer belong to tlv::error.

    Independent Generator¶

    find_package(OpenTLV REQUIRED CONFIG COMPONENTS Generator)
target_link_libraries(my_generator PRIVATE OpenTLV::Generator)

    This loads only Generator, IO and Core. Include opentlv/generator/generator.h; Generator has no Document, Query, Schema, Codec or builtin library dependency. Supply a readable, writable Format and caller-owned output and workspace. The module always provides generation; no Writer capability option selects it.

    The existing header-only opentlv/generator/generator.hpp belongs to Generator. A C++11 consumer can use it with OpenTLV::Generator and the installed C++ headers; C++ headers are always installed. No compiled C++ library is introduced. The shared C++ support headers belong to Core; the Generator target supplies their usage requirements. Its owned generator still allocates scratch/results, while native generation and the caller-buffer facade remain allocation-free.

    Algorithm version 2, seeds, case indices, candidate order, limits, workspace, Writer reconstruction checks and errors are unchanged. See the generation contract.

    Independent Query¶

    find_package(OpenTLV REQUIRED CONFIG COMPONENTS Query)
target_link_libraries(my_filter PRIVATE OpenTLV::Query)
# For Document evaluation and editing:
find_package(OpenTLV REQUIRED CONFIG COMPONENTS QueryDocument)
target_link_libraries(my_editor PRIVATE OpenTLV::QueryDocument)

    Query loads only Core and IO. It provides exact-path matching, text compilation, static plans, streaming and retained execution. Build opentlv_query to compile only that dependency closure. QueryDocument adds Document through public traversal, mutation and callback interfaces; Document never links Query.

    Include opentlv/query/definition.h for name resolution, opentlv/query/program.h for programs and execution, and opentlv/query/features.h for the frontend/set-operation macros and runtime mirrors. OPENTLV_QUERY_FRONTEND and OPENTLV_QUERY_SET_OPERATIONS remain Query-internal CMake options.

    Codec adapters live in the Query-owned query-codec implementation, currently provided by the explicit OpenTLV::QueryCodec integration. Include opentlv/query/adapters.h for them. The base Query target does not compile or link that implementation. C++ environments start without conversion providers; include opentlv/query/codec.hpp and call tlv::configure_query_codecs(environment) before compilation to add NUM, BCD and TEXT. Existing builtin configuration functions still add their own providers explicitly.

    Query conversion callbacks now receive tlv_diagnostic_envelope_t*. Codec-backed callbacks can publish their original diagnostic using tlv_codec_diagnostic_export(). Query preserves the primary location, expression, context and path, stores the raw callback result and violation in reported and violation, and carries delegated frames in detail.causes when cause is CODEC or SCHEMA. Read frames through their producer's copy/import helpers. Direct Reader failures retain detail.reader. This changes the public Query diagnostic ABI and callback signature; rebuild native consumers and update binding layouts.

    Module and feature checks¶

    Module selection is expressed by target links. The old capability-selection options are rejected. python scripts/check_capabilities.py runs all module probes with full Query features and with Query frontend/set operations disabled. scripts/check_module_isolation.py builds each module in a fresh tree, checks symbol/header ownership, and runs relocated installed-package consumers. CI checks static and shared configurations.

    Standalone bindings and tools own their Core dependency checks and pins. Their build scripts must migrate removed CMake options when adopting this revision.

    Built-in standards¶

    Each protocol family has one independently linkable public target. All family implementations are available in the package; consumers select their dependencies by linking targets. Generic modules never link a builtin.

    Target Component Dependencies
    OpenTLV::ASN1 BER, DER, CER, shared identifiers, strict validation, codecs, DER Schema and Query hooks Core, IO, Codec, Schema, Query
    OpenTLV::EMV Framing, DOL, dictionary, codecs, Schema, presentation and Query integration Core, Codec, Schema, Query; ASN1 and SchemaNumber privately; IO for the C++ facade
    OpenTLV::Bluetooth LTV framing, containers, definitions, Schema and codecs Core, IO, Codec, Schema
    OpenTLV::NFC NFC Type 2 framing Core; IO for the C++ facade
    OpenTLV::DHCP DHCPv4 framing, options, codecs and container validation Core, Codec, Schema; IO privately
    OpenTLV::LLDP Framing, definitions, LLDPDU validation and codecs Core, Codec, Schema; IO privately

    EMV retains its existing ASN.1 identifier helper for DOL. BER, DER and CER form one ASN1 library; there are no separate BER/DER/CER targets. DHCP contains only the existing DHCPv4 implementation; no DHCPv6 functionality is added.

    Remove OPENTLV_FORMAT_ASN1, OPENTLV_FORMAT_BER, OPENTLV_FORMAT_DER, OPENTLV_FORMAT_CER, OPENTLV_EMV, OPENTLV_BLUETOOTH, OPENTLV_NFC, OPENTLV_DHCP and OPENTLV_LLDP from CMake invocations and old caches. Supplying either ON or OFF now fails with migration guidance. The former tlv/config.h macros and module availability mirrors are removed; they do not indicate which libraries an application links.

    Recipes¶

    For a generic custom Format and Reader, request only IO (which brings Core):

    find_package(OpenTLV REQUIRED CONFIG COMPONENTS IO)
target_link_libraries(app PRIVATE OpenTLV::IO)

    For BER, DER or CER, request ASN1:

    find_package(OpenTLV REQUIRED CONFIG COMPONENTS ASN1)
target_link_libraries(app PRIVATE OpenTLV::ASN1)

    For Bluetooth or EMV, select the relevant family:

    find_package(OpenTLV REQUIRED CONFIG COMPONENTS Bluetooth EMV)
target_link_libraries(app PRIVATE OpenTLV::Bluetooth OpenTLV::EMV)

    NFC framing itself needs only Core. Add IO explicitly when using Reader/Writer:

    find_package(OpenTLV REQUIRED CONFIG COMPONENTS NFC IO)
target_link_libraries(app PRIVATE OpenTLV::NFC OpenTLV::IO)

    The same target names work with add_subdirectory and FetchContent. To build only NFC and its dependency from source:

    cmake -S . -B build-nfc -DOPENTLV_BUILD_TESTS=OFF -DOPENTLV_BUILD_EXAMPLES=OFF
cmake --build build-nfc --target opentlv_nfc

    The optional OpenTLV::tlv interface brings all families transitively in either language. It has no archive; the separate tlv++ target is removed. Direct archive/shared-library consumers must rebuild, link and distribute the required opentlv_* libraries; builtin symbols are no longer defined by tlv.

    Footprint and bindings¶

    Static linking selects referenced archive members. A BER-only executable need not retain DER, CER, codecs or Query hooks. Shared linking loads the complete ASN1 library and its dependencies. See the measured ASN.1 footprint.

    The C++ facade remains header-only. Individual builtin C++ headers may require explicit integration targets; each functional target supplies its own C++ include directories and C++11 requirement. Standalone language bindings own their pins, feature mappings and migration from removed Core options.
