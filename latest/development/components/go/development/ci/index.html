    Go continuous integration¶

    Go owns public facade tests in root *_test.go files (package opentlv_test), package-internal tests (package opentlv) and private bridge tests in internal/capi. Examples use the public facade. Python tests in tests/ cover build/CI orchestration and evidence validation, not duplicate implementations of Go APIs. Core owns native semantics, native tests and the shared Query corpus/oracle.

    Workflows and coverage¶

    go-pr.yml runs Fast on every pull request to main, without path filters. go-main.yml checks the merged commit on every push to main. go-full.yml is manually dispatched or called by another workflow. All use go-checks.yml and the same matrix/stage definitions in scripts/ci.py.

    Configuration Go PR/Fast Main Full
    Linux amd64, default static 1.22.x Yes Yes Yes
    Linux amd64, minimal static 1.22.x No No Yes
    Linux amd64, default static stable No No Yes
    Linux amd64, default shared stable No No Yes
    Windows amd64, default static, GCC/UCRT stable No No Yes
    macOS arm64, default static, Clang stable No No Yes

    Every configuration checks migration hashes, Python infrastructure regressions, gofmt, go vet, all Go tests with -count=1, external module ZIP consumption (package-check), the reviewed generic API completeness gate, and the version, quick-start, generic format, streaming, schema and generation examples. The package check runs without replace or workspace access using a fresh module cache and local file proxy; it validates module/version/license metadata and a native round trip. Full adds go test -race and GOEXPERIMENT=cgocheck2 on both original Linux static configurations, and runs the reader/writer/errors/codec examples everywhere. Default configurations also run document/query examples and shared Query conformance through the Go executable against the selected Core corpus (--property-cases 0, preserving baseline coverage). Minimal intentionally omits document-dependent examples/conformance and retains existing feature-aware skips. The Linux shared lane tests the runtime library path, including the separately launched Query executable. Race detection is not a substitute for C sanitizers.

    All tiers also validate Actions expressions and shell steps with actionlint. Linux uses Ubuntu 24.04, Windows Server 2022 and macOS 15 runners. Native Python and Go on Windows use the UCRT64 GCC installed by setup-msys2; no MSVC fallback is selected. No sibling repository, preinstalled OpenTLV library or Go workspace is implicitly consumed. The Go module has no go.sum; setup-go caching is disabled. The build helper retains its native-input-specific Go cache within each job. It creates a nested Go module boundary in build/ (or an external build directory) so ./... cannot collect another configuration's generated cgo or toolchain files.

    Core API reference inventory¶

    PR and Full run the independent, informational Core API coverage job. It publishes build/api-coverage.json as go-api-coverage-<tier>-<attempt> and writes the per-header report to the GitHub Step Summary. Missing references, stale ignore patterns and report-job failures do not block the Go quality gate. Invalid input or an unrecognized TLV_API declaration does fail the report job visibly; it does not produce a successful report. Main omits this report, matching the Python coverage workflow. No percentage threshold is enforced. Separately, every native build now requires the reviewed generic contract baseline; generic inventory drift, stale exclusions or pin changes fail that required stage.

    scripts/api_coverage.py is adapted from Python's standard-library reporter at revision 74d7ed756229ab11544d5eba38568ae6f2bfddb0. Its binding-specific configuration is ci/api-coverage.json. It reads TLV_API function and data declarations from Git blobs under tlv/include at the full immutable core-source.json commit, independent of Core's working tree. Headers under tlv/builtins/ are reported separately. Conditional declarations are inventoried without preprocessing; static inline helpers, types and macros are outside this metric. A referenced descriptor can call unreferenced callbacks.

    Only production internal/capi/*.go, *.c and *.h files contribute references. The scanner includes C preambles attached to import "C", while excluding ordinary comments, C/Go string literals (including Go raw strings), bridge tests, examples, documentation and generated build output. It is a lexical inventory, not a call graph: a declaration, identity comparison or conditional reference can count without proving an operation is reachable through the public Go facade. Public Go API and lifetime/error tests remain the evidence for usable behavior; Core owns native semantics and its shared Query corpus.

    Each exclusion has a reason in the configuration and the JSON/Markdown report. The initial 44 exclusions covered Go storage primitives, reduced-output wrappers whose richer diagnostic operations are used, and callbacks installed by bound format/codec constructors. Subsequent reviews below account for the remaining generic symbols. For example, #21 maps tlv_copy_element to canonical diagnostic Writer serialization, not merely to copying a Go byte slice. Builtins are not blanket ignored; their 291-symbol inventory is visible but parity is outside epic #15.

    The PR report reads the previous lock at github.event.pull_request.base.sha and inventories both exact Core commits. Added symbols include their current reference/ignore status; removed symbols retain their former header and kind. An unchanged pin is stated explicitly. This is a symbol-set diff, not a C ABI or signature compatibility check. A standalone Full run has no implicit base.

    From the repository root:

    python3 -B scripts/api_coverage.py --output build/api-coverage.json
python3 -B scripts/api_coverage.py --base origin/main --output build/api-coverage.json
python3 -B scripts/api_coverage.py --core ../opentlv --base HEAD --output build/api-coverage.json

    The default shallow-fetches the exact pin(s) into build/api-coverage/core.git. --core explicitly selects an existing Git object store and never fetches into or changes it; every requested commit must already exist there. Its checked-out HEAD need not equal the lock. --summary PATH appends Markdown, --base-commit SHA selects a previous Core revision directly, and --commit SHA is an explicit exploratory override, not pinned-build evidence. Use python on Windows.

    Before coding #21, Go 68af66efd7c482a1a8bf9e46e4b5ab2d294449b1 was inventoried against Core cb3caed5b09706ce11ecfae839397fd4f99d0025: 162 referenced, 15 missing and 120 excluded generic symbols.     ci/api-completeness.json records the exact pin, every generic header's symbol disposition, exclusion reasons and eleven reviewed public contract families.     Every PR, Main and Full native build runs scripts/api_completeness.py after the runtime tests/package check, using that build's exact Core Git object store.     python3 -B scripts/api_completeness.py --core ../opentlv --output build/api-completeness.json

    For a Core pin update, first generate the informational report with --base against the previous binding revision. Run the required tests and Full configurations; never refresh the baseline solely to restore a score. api-completeness.json and the per-header log accompany each build artifact.     Quality gate and evidence¶

    Configure branch protection to require the PR workflow's Go quality gate job (shown under the reusable checks job). Workflow files cannot configure repository branch-protection settings. Full has the same named aggregate gate in its own workflow; it does not run automatically on each PR.

    The gate runs even when a dependency fails or is skipped. It requires successful plan/build/workflow-validation jobs, exactly the expected matrix records, every planned check in order, matching logs and clean pinned-Core receipts. Records must match repository, checked-out/event SHA, workflow/ref, run ID, attempt, tier and CI definition hashes. Duplicates, missing results, local results and mixed Core inputs fail the gate. A failed build overwrites stale success evidence; the gate removes any previous success summary before validation. Re-run all jobs after a failure: evidence from an earlier attempt intentionally cannot satisfy a later attempt's gate, even if that earlier matrix row passed.

    Artifacts named go-build-<tier>-<configuration>-<attempt> contain record.json, per-check logs and Query failure evidence when available. Each completed Go stage retains its own Core receipt, rather than relying only on the helper's last core-selection.json. Records include exact Go/compiler/CMake/Ninja/Python versions, commands, durations, log hashes, configuration and Core input/native digests. go-quality-<tier>-<attempt> contains the successful aggregate summary. Setup failures may have no record; that missing evidence still fails the gate. These are CI execution records, not signed release attestations.

    Documentation updates¶

    After successful Main checks, go-main.yml records whether documentation, examples or their version/dependency metadata changed since the previous successful Main push. Failed or cancelled intervening pushes remain included. The docs-notification-<attempt> artifact identifies the exact commit and run.

    docs-notify.yml runs only after successful official Main pushes. It reads that attempt's JSON without checking out or executing producer code, validates its identity and sends component-docs-updated to OpenTLV/opentlv-docs. Configure OPENTLV_DOCS_DISPATCH_TOKEN with access to dispatch to that repository; the credential is available only to the final notification step. No token is needed when there are no relevant changes. A missing token or failed dispatch fails the notifier and can be retried without rerunning native tests.

    The portal's documentation update policy validates the successful Main run and opens or updates a reviewed pin proposal on automation/component-go. Replays are idempotent; stale or divergent revisions are rejected. A notification does not deploy Pages, invoke Docs Full, or establish a Go release.

    The portal mounts this repository's docs/ independently of Core and preserves Go-owned source/edit links and example links at the selected Go commit. Its version selector describes the portal snapshot, not BindingVersion or the linked Core version. docs-examples.json supplies the Go quick-start tab from the same checkout; its version must match BindingVersion. No runtime compatibility result for the portal-selected Core is implied by that catalog.

    Go currently has no release workflow or independent versioned documentation snapshot. Merge Go changes first, then review and merge the exact Go SHA into the portal manifest and validate the locked build. Local preview permits dirty sources but cannot authorize publication. Hosted notification, portal CI, Pages deployment and published URL checks remain separate evidence.

    Local reproduction¶

    Install the prerequisites from the development guide, using a compiler and Go installation that match the selected native platform. From the repository:

    python3 -B scripts/ci.py matrix --tier full
python3 -B scripts/ci.py build --tier pr --configuration linux-default
python3 -B scripts/ci.py build --tier full --configuration linux-default
python3 -B scripts/ci.py build --tier full --configuration linux-minimal
python3 -B scripts/ci.py build --tier full --configuration linux-shared
